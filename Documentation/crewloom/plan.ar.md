# خطة ذاكرة التغيير في Crewloom

الخطة الحاكمة: [IMPLEMENTATION-PLAN.md](../../IMPLEMENTATION-PLAN.md).

## تغيير الاتجاه — 2026-10-29

الأمر الأصلي المنشور في `crewloom-git-v0.1.0` أصبح نسخة مرجعية مجمدة. لا ميزات
جديدة على `crewloom-main`. العمل الجديد طبقة ذاكرة فوق Git المثبت كما هو، ولم يُكتب
منها كود بعد.

السبب: Git يخزن النسخ ويحسب الفروق ويسترجع المحتوى أصلًا. تطوير فورك C يكرر هذا
العمل، ويفرض دمج كل إصدار جديد من Git وإعادة اختبارات التوافق، ويُلزم المستخدم بنسخة
Git ثانية. القيمة غير المثبتة هي اختيار التغييرات المرتبطة بالمهمة وتحديثها، لا التخزين.

الطبقة المقترحة تستدعي أوامر Git الأساسية (`ls-files -s` و`cat-file --batch`
و`hash-object` و`commit-tree` و`update-ref` و`diff` و`log`) ولا تعدّل Git ولا
الـindex ولا HEAD. تحفظ اللقطات في مخزن bare خاص داخل مجلد Git لكل worktree كما في
النموذج الأولي، وتفصل محتوى staged عن محتوى ملفات العمل، وتراقب الملفات بأحداث نظام
التشغيل. مكان الطبقة ولغتها ومالك الحزمة قرار مفتوح.

**بوابة القياس أولًا:** مهام Crewloom حقيقية بملفات مرتبطة معروفة، تُقارن فيها الرموز
والتكلفة ونجاح المهمة والملفات المفقودة بين سياق `git status/diff/log` العادي وسياق
الطبقة. لا تُبنى الطبقة كاملة إلا إذا قلّت الرموز أو التكلفة دون خفض نجاح المهام،
وتُنشر الأرقام كما هي حتى لو كانت سلبية.

اختبارات القبول في النموذج الأولي تبقى مرجعًا لسلوك الطبقة.

## أرشيف: خطة النموذج الأولي 0.1.0

ما يلي هو خطة الشريحة الأولى داخل نواة Git المعدلة، محفوظ كما هو للمرجعية.

### قرار المجلس

مراجعتان مستقلتان فحصتا المصدر، ومراجعة Claude Code Sonnet 5.5 مستقلة نقدت
حزمة التصميم دون أدوات. الموافقة مشروطة بالاختبارات؛ اتفاق الموديلات ليس إثباتًا.
المصدر الأساس Git v2.56.0. العمل على crewloom-main في فورك معزول؛ Git النظام لا يُستبدل.

### التنفيذ

1. بناء Git الأصلي للتحقق من البيئة.
2. مخزن Git محلي مستقل للذاكرة بصلاحيات المالك، دون remotes أو alternates.
3. حفظ نسخ المصدر المتتبع المختار: محتوى index ومحتوى worktree منفصلان.
4. استرجاع سياق محدود وتاريخ وفروق بايتات وملاحظات مرشحة مرتبطة بمصادرها.
5. أمر builtin أصلي ومراقبة أمامية تلتقط التغييرات المحفوظة تلقائيًا أثناء تشغيلها.
6. اختبارات فعلية وثائق عربية وإنجليزية ثم إصدار رسمي والتحقق من CI عبر gh.

الذاكرة معطلة حتى يحدد المستخدم نطاقها. لا استدعاء AI في التخزين والمقارنة والاسترجاع.
مصدر الموديل والجلسة والمهمة بيانات معلنة من المضيف، وليست هوية مثبتة. الأصل المجهول
يظهر unknown. لا التقاط مضمون لكل ضغطة أو تعديل عابر بين اللقطات.

الملاحظات نصوص بيانات غير موثوقة وليست تعليمات؛ ثبات المصادر لا يثبت صحة الاستنتاج.
يتأجل Tree-sitter والتحليل الدلالي الكامل وتكامل Crewloom وتوصيل add/commit إلى تغيير مستقل.
الاسترجاع يعتمد على مصادر ومقتطفات؛ وجود ذاكرة لا يعني ضمان تذكر الموديل لها.

### القبول

نثبت سلامة index وHEAD وشجرة العمل ومخزن كائنات المصدر، وفصل staged عن dirty،
وصحة تاريخ التغييرات ومواضع البايتات، وعزل worktrees، وSHA-256، والتزامن والانقطاع
وبقاء التاريخ بعد gc. نختبر أن push --mirror وclone وbundle للمصدر لا تنقل الذاكرة.
يظهر أي مدخل غير مدعوم أو حذف بسبب الميزانية بوضوح؛ لا نجاح مضلل.

التقييم الأول يقيس بايتات المخرجات الفعلية فقط؛ لا يُحوّلها إلى نسبة توفير كوتا أو زيادة ذكاء.

### نتيجة التنفيذ المحلية — 2026-10-28

تم بناء الأمر الأصلي داخل Git واجتازت الفحوصات المحلية: بناء `DEVELOPER=1`،
و23 اختبار سلوك للذاكرة، و9 اختبارات سلامة، و674 اختبار توافق Git مختارًا
(706 اختبارًا بالمجموع)، إضافة إلى `git diff --check`. لم نشغّل sanitizer أو
اختبارات Windows محليًا. الإصدار لا يُعد منشورًا قبل نجاح CI البعيد والتحقق منه
بأداة `gh`. تفاصيل النطاق والقيود والنتائج في
[ملاحظات الإصدار](RELEASE-NOTES.md) و[الدليل العربي](README.ar.md).
